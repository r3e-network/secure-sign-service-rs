# Neo Signer RS v0.2.0

This release turns the Neo N3 council signer into a supervised, restart-safe
service with an optional fail-closed daily GAS aggregation path.

## Highlights

- Allowlisted `SignTransaction` is available only when explicitly enabled at
  deployment and only for the configured GAS destination.
- The daily sweeper requires two independent Neo RPC providers to agree on
  balance, height, VM result, and fees before signing.
- A disk-backed anti-equivocation journal bounds gateway memory while preserving
  durable consensus and economic idempotency records.
- KMS recipient attestation binds wallet unlock to the deployed Nitro EIF.
- systemd health recovery and a randomized host-local daily fallback complement
  the external 09:00 Asia/Shanghai automation routine.
- Neo N3 transaction IDs now use the correct single SHA-256 derivation for
  broadcast confirmation.
- Transitive `anyhow`, `bytes`, `h2`, `rand`, and `rpassword` dependencies are
  updated to patched releases across the root and independent SGX workspaces.

## Safety Properties

- Consensus signing remains available when economic signing is disabled.
- External automation can only start the audited systemd sweep unit; it cannot
  select a destination or call the enclave directly.
- A confirmed daily plan is byte-identical on retry and cannot produce a second
  transaction for the same Asia/Shanghai day.
- No production wallet, WIF, password, destination, KMS ciphertext, instance
  identifier, transaction hash, or PCR value is included in the source release
  or attached artifacts.

## Upgrade Notes

1. Review `CHANGELOG.md` and `docs/RELEASE.md` before deployment.
2. Build the generic ARM64 binaries and the production EIF separately.
3. Rotate KMS attestation policy through old-plus-new PCR0, cold-start the new
   EIF, then remove the previous measurement.
4. Verify fresh KMS unlock, signer status, systemd state, live consensus journal
   writes, chain progress, and daily sweep idempotency.
5. Keep the host fallback timer enabled after the external routine is verified.

The release archive contains generic Linux ARM64 binaries only. Production EIFs
remain private deployment artifacts and are never published.
